# 实验依据与补实验计划

更新：2026-09-10。配套阅读：[论文思路与大纲](ICLR2027_论文思路与大纲.md)。以下区分原始文件可核验结果、文档记录和待完成实验。没有启动训练或付费 API 调用。

## 1. 当前数据与方法基础

| 数据 | Idea 新颖性样本 | Pair 样本 | 说明 |
|---|---:|---:|---|
| Graph ML | 5,225 | 21,183 | 历史正式模型数据；Novelty train/dev/test = 3,657/784/784 |
| CV | 8,291 | 36,238 | 数据已构建；本次未找到对应完整模型结果 |
| Time Series | 7,595 | 35,455 | 数据已构建；本次未找到对应完整模型结果 |
| Mixed 三领域 | 21,111 | 92,876 | 合并后重做时间划分；Pair 仍全部在各自领域内 |

来源：[多领域 README](../../multi_domain_dataset/README.md) 及各目录 `dataset_manifest.json`。三领域混合不能声称已提供跨领域 Target–Prior 配对；Graph 与 CV/TS 标注模型不同，也不能把所有域差异都解释成知识迁移。

实现主线：Pair Cross-Encoder → 确定性排序 → Joint Coverage MIL → EGRD。当前 EGRD 有单元覆盖与残差、交互残差、上下文特征及辅助头。公式已对照 [训练代码](../../model/novelty_pipeline/train_residual_egrd.py)；但历史 v23 与当前默认 sparsemax 配置不是同一模型，最终论文应依据冻结版本描述。

## 2. 历史域内结果：两个预测头必须分行

从 [原始 metrics.json](../../results/final/egrd_v23/metrics.json) 的 `test` 读取，N=784：

| 同一历史 checkpoint 的输出 | Accuracy | Macro-F1 | Balanced Acc. | QWK | Ordinal MAE ↓ | High-F1 |
|---|---:|---:|---:|---:|---:|---:|
| `novelty_direct` | 0.6314 | 0.5460 | 0.5769 | 0.7562 | 0.3801 | 0.0132 |
| `novelty_final` | 0.6033 | 0.6100 | 0.5996 | 0.7534 | 0.4273 | 0.3586 |

**不能把 Accuracy 0.6314、Macro-F1 0.6100、QWK 0.7562 合成一行“最佳模型”。** 那是对两个输出逐指标取优，不对应一套实际预测。建议后续按预先确定的 dev 规则选择主输出；历史两个输出都完整保留，避免用 test 挑主头。

历史 checkpoint 元信息：seed 173，best epoch 3，`final_checkpoint=novelty`，`selection_metric=novelty_selection_score_constrained`。高新颖度是主要弱点，direct 的高类召回仅 0.0067。不能只用总体 Accuracy 描述能力。

其他可用于方法分析的历史结果：实质差异分数 Spearman 0.7521；细残差类型 Macro-F1 0.4482；`nontrivial_combination` F1 0.2396。这些主要反映对银标签的拟合，不等于真实贡献分解已经准确。

上游结果可引用 [结果目录说明](../../results/README.md)：Pair Macro-F1 0.4917；Prior Recall@5 0.9424、NDCG@5 0.9087；Joint score Spearman 0.6809。检索指标是在已有候选集合上评估，不能写成对完整文献世界的召回率。

## 3. 外部人类标签：目前有信号，但迁移还弱

RINoBench 共有 1,381 个研究 Idea，来自人类专家判断的评测数据；仓库采用 1,104 train / 277 test。原生 1–5 标签在本项目中折叠为四级，4/5 合并，因此本文四级数字不能直接当作原论文五级结果。[原论文](https://aclanthology.org/2026.lrec-1.370/)

### 3.1 分块结果以本地原始文件为准

[pooled.json](../../results/rinobench_chunked/pooled.json) 中 `selected_on_their_train` 明确选择 `pred_substantive_delta_score` + `min`：

| 设置 | N | Accuracy | Macro-F1 | QWK | MAE ↓ | Spearman | Pairwise AUC |
|---|---:|---:|---:|---:|---:|---:|---:|
| 25 篇分 5 组，每组 5 篇，min 聚合 | 277 | 0.3574 | 0.3203 | 0.2075 | 0.8592 | 0.1896 | 0.5875 |

这不是严格零样本：聚合规则及切点使用了 RINoBench train。训练权重冻结也不等于没有使用目标域标签。

[全系统横向对照文档](../../docs/baselines/RINoBench-全系统横向对照.md) 还记录了搜索切点版本 Macro-F1 0.3286、QWK 0.2170，但当前 `pooled.json` 不是这组结果；应补齐对应配置、预测和校准产物后再放主表。该文档中的 bootstrap 区间也需配套统计产物后正式引用。

分块 min 是值得研究的推理策略，但**它不是单元级 Noisy-OR 的数学等价实现**。每块独立编码、独立生成槽位，不同块可能分别覆盖不同单元；标量 min 无法精确合并全部单元覆盖。应称为保守聚合启发式，并检查噪声证据造成的过度压低。

### 3.2 最新适配实验也应进入判断

来自 [zeroshot/by_corpus.json](../../results/rinobench_adapt_zeroshot/by_corpus.json) 与 [mixed/by_corpus.json](../../results/rinobench_adapt_mixed/by_corpus.json)：

| 训练设置与输出 | 自有 test Macro-F1 | RINoBench test Macro-F1 | RINoBench QWK |
|---|---:|---:|---:|
| 新版仅自有数据训练，`novelty_final` | 0.5965 | 0.1824 | 0.0601 |
| 新版加入 RINoBench train 适配，`novelty_final` | 0.6165 | 0.1674 | 0.0233 |

mixed 是“自有语料 + RINoBench”适配实验，与三领域 `multi_domain_dataset/mixed` 不同。适配后的 ordinal 头在外部测试集全部预测 high，QWK=0。适配模型再做切点拟合时，`pred_novelty_score_composed` 的外部 Macro-F1 为 0.3002、QWK 为 0.0531；这又是另一种输出协议，应单列。

这些结果说明，当前这一版混合适配没有获得稳健外部判别力，不能只挑其自有数据 0.6165 写“新版本全面提升”。训练版本和输出协议不同，也不能把差异完全归因于某一个模块。

### 3.3 现有基线怎么使用

- 自有 784 条上已有 Qwen、GPT 的直接判断/RAG 结果。例如 [full_model_comparison/summary.md](../../results/llm_eval/full_model_comparison/summary.md) 中 GPT-5.6-sol Top-5 RAG 的 Macro-F1 为 0.3731、QWK 为 0.4251；直接判断 QWK 为 0。模型名称按运行记录如实报告。
- 外部基准文档中 Qwen K=25 的 Macro-F1 为 0.2477、QWK 为 0.1815，属于零样本协议。EGRD 目标域校准行应与其分区，并补同预算校准对照。
- GraphMind/UKPLab 使用统一 Qwen 骨干的结果是**适配复现**。GraphMind 的检索通道实际使用证据还需单列核验，不能只因入口候选相同就认为最终消费证据完全相同。
- 自有测试集 UKPLab 文档为 606/784、DeepReviewer 为 694/784。优先补齐失败样本；否则报告完成率及共同成功子集，并明确可能的选择偏差。
- 原作者发布的预测和本地适配复现分表；输入、骨干和证据预算不同的系统不作为纯方法消融。

## 4. 现有分析里需要修正的论证

这些是新论文应采用的口径，本次没有修改历史实验记录。

| 原记录或可能的说法 | 论文应采用的表述 |
|---|---|
| “QWK 不受阈值位置影响” | QWK 基于离散标签，会随切点改变。用原始连续分数的 Spearman/成对排序指标分析排序质量。 |
| “四分类随机 Macro-F1 就是 0.25” | 0.25 不是任意类别分布下的随机 Macro-F1 基线；报告实际类别分布下的常数/随机参照。Balanced Accuracy 的相应随机参照才是 0.25。 |
| “检索是唯一起作用的变量” | 本组检索实验显示改善，不能排除训练、校准、输入格式等其他因素的作用。 |
| “低 MAE 是塌缩症状，因此不用看” | MAE 衡量序数误差，仍然有意义。和类分布、Macro-F1、QWK 联合解释；如方法 MAE 更差，要如实报告。 |
| “Prior 多导致低新颖性是预期关系，不算混杂” | 相关 Prior 可以降低残差，但 Prior 数量和主题也可能成为捷径；需要控制数量、相关性和配对关系的干预。 |
| “跨块取 min 保证所有证据联合覆盖正确” | 标量保守聚合不等于跨块语义单元的联合支持；效果及误差需实验验证。 |
| “TF-IDF 没找到捷径，所以模型没有捷径” | 弱探针阴性不能排除强编码器利用捷径。 |

现有 [TF-IDF 审计](../../results/validity_b/shortcut_ablation/summary_tfidf.md) 反而提示需要继续检查：Prior-only QWK 0.2103，高于 Target+Prior 的 0.1964。它不能证明 EGRD 有同样问题，但足以支持补强探针。

此外，历史 `estimated_unit_coverage_vs_gold_joint` 的 Pearson 达 0.9922，但它与上游预测 Joint 的 Pearson 仅 0.5457。这个差异本身不能证明泄漏；应检查字段来源、模型输入、监督重建指标和预测导出过程，避免把高相关直接当成解释正确的证据。

## 5. 按优先级补实验

### P0：先把论文的主要主张验证完整

| 工作 | 最小可交付结果 | 它排除的解释 |
|---|---|---|
| 冻结版本与结果 | 数据哈希、代码版本、配置、checkpoint、完整预测；指定 dev 选模规则和主输出 | 历史与新代码混用、跨头取优 |
| 收回已有消融 | baseline/B1/B2/C1 的配对 seeds 173/174/175，均值±样本标准差 | 小幅提升只是随机波动 |
| 同骨干强对照 | Target-only；同 Pair 编码/MIL 直接分类；上游数值特征 MLP；完整 EGRD | 收益来自骨干、训练预算或上游分数，而非残差结构 |
| 无交互分支 | 单独关闭交互路径并重训；保留其余配置 | M=1 同时移除了多单元和交互，无法单独归因 |
| 证据依赖 | 真实、随机日期合法、Prior-only、关键证据删除与随机删除 | 依赖主题/数量/元数据而非具体覆盖关系 |
| 时间与实体隔离 | canonical Idea、来源论文、近重复跨 split 审计；所有上游训练均排除下游 test target | 只对最终阶段做时间划分仍可能留下上游或实体泄漏 |
| 小规模人工核验 | 约 100–150 个分层样本，至少两名标注者，独立打分后讨论分歧 | 银标签规则自洽被误认为人类认可 |

人工核验优先覆盖 moderate/high 边界、组合创新、相似但不覆盖和缺证据案例。标注者先看文本和证据，不看模型预测；记录一致性、覆盖判断和新颖性判断。若资源不足，不将未实施的标注协议写成已完成。

已有 [第一批脚本说明](../../ablation/README.md)、[第二批说明](../../ablation/ROUND2.md) 记录了服务器运行计划和进度；本次没有在本地 `results/` 下找到其正式 summary/paired_summary，不能填写未取回的数值。

复用上游的 EGRD 消融只回答“给定同一上游产物时的结构收益”。当前代码曾修复 EGRD gradient checkpointing 问题，应确认预期解冻层有非零梯度；Pair/Joint 要分别检查。新消融不能直接减去历史 0.6314。

证据替换时，文本、Pair 分数、排序、Joint 预测和全局特征要同步重算。单独打乱文本、保留原来的数字证据，只能称为局部通道干预。删除/加入证据后的整体新颖性方向并非无条件单调；单元 Noisy-OR 在固定支持值下单调，不代表重新编码后的整网有此保证。

### P1：加强 ICLR 说服力

1. **公平目标域校准。** 将 RINoBench 1,104 条划为 fit/validation，校准及选规则仅用它们。给 EGRD 与能输出有序分数的 baseline 同等校准数据；纯零样本、仅校准、梯度适配分别报告。粗粒度 LLM 整数输出的 test oracle 重映射只能放附录作诊断。
2. **证据预算实验。** 对照 K=5、K=25 和 5×5 分块，记录真实消耗的文本量、调用量、延迟及设备。min/mean 等规则仅在开发集选；加入重复与无关证据测试。不要将 API 排队差异写成架构速度倍数。
3. **多领域泛化。** 先做 Graph→CV/TS 的冻结模型评测，以及各域监督训练或三领域混合的分域评测；同域与迁移协议分开。训练 profile、时间切点与标注模型差异全部记录。
4. **解释验证。** 将高支持 Prior 的删除效果、槽位定位的人类核验、语义健康指标结合起来；对组合样本核验“共同支持”是否真的等于覆盖其组合关系。

### P2：有余力再做

更大骨干、更多 agent baseline、M=2/4/16 全量扫描和大量槽位正则组合。除非核心消融暴露明确问题，否则收益小于 P0/P1，不建议在截稿前扩张。

## 6. 统计与成稿规则

- 每行结果绑定一个模型版本、checkpoint、预测头、阈值和测试样本集合。不同预算或不同校准协议明确标出。
- 同 seed 配对比较，报告至少三 seed 的均值和样本标准差；只做 EGRD 重训时说明上游固定。
- 在完整预测上做配对 bootstrap；若多个 Idea 来自同一论文，优先按论文分组重采样。多次查看同一个外部 test 后形成的改进要承认探索性，尽可能保留新的确认集。
- Macro-F1 与 QWK 共同反映分类和序数一致性，MAE/High-F1 及预测分布补充解释。连续排序指标与类别指标分开。
- 论文不从 `best_metrics.json` 的逐指标取优表生成主表；每个数字回到原始预测或对应 `metrics.json`。
- 现有 [results README](../../results/README.md) 记录部分历史 checkpoint/预测曾损坏。最新适配目录虽然有 checkpoint 文件，本次没有加载验证；重现材料需单独核验可加载性和预测完整性。

在上述结果齐备前，摘要可以介绍问题和方法，结果句应保守；不要预填“跨领域显著优于所有强基线”或“解释具有因果忠实性”。
